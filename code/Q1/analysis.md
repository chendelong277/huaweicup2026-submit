# 问题一任务分析与方案取舍

> **三分钟摘要**：本文档记录问题一的任务拆解、数据预检结论、方案选择理由和核心结果。主要结论：默认 20% 返航余量下 18 架次即可送完全部 80 箱，并给出了余量从 10% 到 40% 的完整敏感性——余量加到 40% 时 S008 连空载往返都飞不成，这是硬性边界而非组批问题。术语看不懂可查仓库根目录 `shared/glossary.md`。

## 任务矩阵

| 项目 | 本模块处理 |
|---|---|
| 输出 | 45 个“服务区—机型”最大安全载荷；逐服务区货箱组批；架次、能耗、累计作业时间；返航余量敏感性 |
| 输入 | O01 与 S001-S015 坐标和海拔、30 m DEM、A/B/C 机型参数、80 个不可拆分货箱 |
| 硬约束 | 单点 O01→Si→O01；不跨服务区；每箱恰好一次；质量、体积、返航能量均合规 |
| 软目标 | 架次数、总能耗、累计作业时间 |
| 后续接口 | Q2/Q3 的节点、航段、载荷—能耗判定和单点能力基线 |

## 数据预检结论

- 节点表包含 1 个调度中心和 15 个服务区，需求表包含 80 个唯一货箱。
- 三种运输机型的额定载荷分别为 25、30、80 kg，可用体积分别为 0.060、0.073、0.250 m³。
- 三机型附件默认返航电量下限均为 20%。
- 节点全部位于 DEM 范围内；所有 O01—服务区直线均未穿过 NoData 像元。
- 实际服务区编号为 S001-S015，本模块尊重附件编号，不擅自改写为 S1-S15。

## 方案选择

参考给定思路文档，本模块采用“连续能力计算 + 离散精确组批”的两层结构：

1. 对每个机型—服务区组合，用二分搜索求最大安全质量载荷。
2. 对每个服务区枚举全部货箱子集和可行机型，用位掩码动态规划求精确集合划分。
3. 主方案采用词典序：先最少架次，再最小能耗，最后最小累计作业时间。
4. 另求“能耗优先”和“时间优先”方案，直接量化目标冲突。
5. 将返航余量从 10% 扫描至 40%，重算安全载荷和组批。

该选择比 FFD 基线更适合本题：单个服务区最多 15 箱，精确子集动态规划规模可控，能够给出主目标下的全局最优组批，而无需依赖随机启发式。

## 核心结果

默认 20% 返航余量下，主方案为 18 架次、59.263908 kWh、32804.873419 s。服务区 S001、S002、S003 各需 2 架次，其余服务区各 1 架次。S001 使用 2 架次 C 型；S002、S003 各使用 1 架次 B 型和 1 架次 C 型；S004-S008 使用 C 型；S009-S015 使用 B 型。

“能耗优先”方案使用 19 架次，能耗为 59.165853 kWh，比主方案节省约 0.098056 kWh，但增加 1 架次和约 1668.083 s 累计作业时间。时间优先方案与主方案一致。因此选择架次优先具有清晰依据：用极小的能耗代价避免额外架次和明显的时间增长。

## 敏感性结论

| 返航余量 | 是否可完成全部货箱 | 架次 | 总能耗 kWh | 累计作业时间 s |
|---:|:---:|---:|---:|---:|
| 10% | 是 | 18 | 59.263908 | 32804.873419 |
| 15% | 是 | 18 | 59.263908 | 32804.873419 |
| 20% | 是 | 18 | 59.263908 | 32804.873419 |
| 25% | 是 | 19 | 61.213341 | 34598.655972 |
| 30% | 是 | 20 | 67.383491 | 36623.294903 |
| 35% | 是 | 25 | 78.214472 | 45558.383054 |
| 40% | 否 | — | — | — |

40% 余量时，S008 的三种机型即使空载往返也不能满足能量上限，因此不是增加架次能够修复的问题；这构成安全余量的可行性边界。

## 验证证据

- 内部正确性：80 箱恰好一次；18 个批次全部通过质量、体积、能量和同服务区检查。
- 稳健性：完成 7 个返航余量场景；识别出 25%、30%、35% 的阶梯式架次增长及 40% 的不可行阈值。
- 复现性：保存原始输入 SHA-256、代码 SHA-256、运行时间、参数和确定性求解说明。
